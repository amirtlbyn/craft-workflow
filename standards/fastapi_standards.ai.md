# FastAPI Standards — services built on FastAPI, Pydantic v2, and SQLAlchemy 2.0

> **Scope & ownership:** factual `*.ai.md` (bot-maintainable), written for craft-workflow 0.7. It applies when
> `bin/craft-stack` detects the `fastapi` stack. Python language style still comes from
> [python_code_style.ai.md](python_code_style.ai.md), and the engineering standards TS-1 to TS-5 of
> [technical_standards.ai.md](technical_standards.ai.md) apply to any database a FastAPI service owns. A team that
> adopts this file can rename it to `.human.md` to make it human-owned.

## Layout

- `app/main.py` creates the app and its `lifespan`. Nothing else runs at import time.
- `app/api/` (or `routers/`) holds routers, one module per resource. `app/services/` holds business rules.
  `app/db/` holds the engine, the session dependency, and the ORM models. `app/schemas/` holds Pydantic models.
- `app/settings.py` holds one `BaseSettings` class. Code reads settings through a dependency, never `os.environ`.

## Routers

- A router function parses, calls one service function, and returns a response model. No query, rule, or outbound
  call in it.
- Every endpoint declares `response_model` or a return annotation, a status code, and its auth dependency.
- List endpoints paginate: `limit: int = Query(50, ge=1, le=200)` and a cursor or an offset.

## Schemas

- Pydantic v2. Input models set `model_config = ConfigDict(extra="forbid")`.
- Money is `Decimal` (with `max_digits`, `decimal_places`) or an `int` of minor units. Never `float`.
- Response models list the fields the client gets. An ORM object is converted with `model_validate(obj,
  from_attributes=True)`, never returned as is.

## Errors

- Services raise domain exceptions. One `@app.exception_handler` per family maps them to the repository's error body.
- `HTTPException` belongs in routers and dependencies only.
- A 500 never echoes an exception message to the client. It is logged with the request id.

## Database

- SQLAlchemy 2.0 typed models (`Mapped[...]`, `mapped_column`). Relationships set `lazy="raise"` in async services.
- One session per request from a dependency. Transactions with `begin()`. No outbound call inside one.
- Alembic for every schema change. Read and edit every autogenerated migration. TS-1 applies: additive first,
  backfill in batches, destructive steps in a later deploy.
- Pool size × workers stays under the database's connection limit. The sum is written in the spec when it changes.

## Concurrency

- `def` or `async def` follows `bin/craft-stack concurrency`. The `fastapi-async` skill holds the async rules.
- A blocking call inside `async def` is a defect at High.

## Security

- Authentication is a dependency (`Depends(current_user)`), applied at the router or the endpoint.
- Object-level authorization scopes the query to the user: `where(Order.user_id == user.id)`.
- CORS origins come from settings. `allow_origins=["*"]` with credentials is a defect.
- Secrets are `SecretStr` and never logged, returned, or put in an exception message.

## Tests

- pytest. `httpx.AsyncClient(transport=ASGITransport(app=app))` for async suites, `TestClient` for sync suites.
- `app.dependency_overrides` replaces a dependency, and the fixture clears it after.
- A real database in a container for queries, constraints, and locks.
- Every test names its criterion ID first in its docstring.
